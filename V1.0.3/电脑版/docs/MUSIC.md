# 音乐盒 · 用 MIDI 在游戏内播放音乐

> 控制台页面：**音乐盒**（左侧导航第 5 项）
> 入口文件：`admin/midiplayer.js`（纯前端，无需额外依赖）

## 它是怎么工作的

```
MIDI 文件 → 浏览器解析（音符/时值/音色/鼓）
          → 按时间轴调度
          → 每 25ms 预排 160ms
          → POST /api/send { command: "/playsound ..." }
          → Qiuper WS 服务 → 游戏内客户端执行
```

- 播放完全在前端调度，Qiuper 只负责把 `/playsound` 命令转发给已连接的游戏
- 同时提供**本地试听**（WebAudio 合成），没连游戏也能先听效果
- 游戏里的声音由 `playsound` 在**每个玩家自己的位置**播放（`@a ~ ~ ~`）

## 命令格式

```mcfunction
/playsound note.harp @a ~ ~ ~ <音量> <音高>
```

- **音量**：0.1 ~ 1.0（由 MIDI velocity × 界面音量滑块得到）
- **音高**：0.5 ~ 2.0（基岩 playsound 限制），以 F#3（MIDI 54）= 1.0 为基准，
  超出范围会自动移八度，公式 `2^((note-54)/12)`
- 鼓通道（第 10 通道）自动映射：

| MIDI 鼓 | 音色 |
|---|---|
| 35 / 36 底鼓 | `note.bassattack` |
| 38 / 40 军鼓 | `note.snare` |
| 42 / 44 / 46 镲片 | `note.hat` |

## 支持范围

- 标准 MIDI 文件：**SMF 格式 0 / 1**
- 音符 on/off、tempo 变速、program change、鼓通道
- 多轨自动合并
- 不支持：SMPTE 时间格式、MIDI 2.0、RMI 封装、外部音源

## 使用步骤

1. 打开控制台 → **音乐盒**
2. 点「上传 MIDI」（或把 `.mid` 文件直接拖进窗口）
3. 确认信息（音符数、时长、通道、乐器映射）
4. 「播放」→ 本地试听 + 同时发到游戏（如果游戏已连接）
5. 可调：音量、速度（0.5x–2x）、循环、本地试听、发到游戏

## 注意事项

- **需要游戏已连接**：控制台右上角显示「游戏未连接」时，命令发送会失败并在日志里提示（本地试听不受影响）
- **指令频率**：服务器对指令有限制；密集曲目（每秒 >10 个音符）建议降到 0.75x/0.5x，或关掉「发到游戏」只本地听
- 同一个音同时发出多条 playsound 会被服务器合并/截断，和弦建议 ≤4 个音
- 音量参数上限 1.0；如果觉得太小，可以在游戏设置里调高「音乐/玩家」音量

## 调试接口（F12 控制台）

```js
CQMusic.state()                       // 播放状态、已发送条数
CQMusic.loadBase64(b64, "test.mid")   // 直接加载
CQMusic.commandFor({ch:0,note:60,vel:100,prog:0}, 80)
// → "/playsound note.harp @a ~ ~ ~ 0.63 1.414"
CQMusic.soundFor(80)                  // "note.pling"
CQMusic.pitchFor(60)                  // 1.4142
```

## 游戏内歌词 / 曲名显示（titleraw）

音乐盒的「歌词/曲名（titleraw）」勾选项会在播放时向游戏发送：

`mcfunction
# 播放开始：主标题显示曲名
/titleraw @a title {"rawtext":[{"text":"♪ 测试歌词.mid"}]}

# MIDI 里的歌词事件（meta 0x05 / 0x01）：逐行显示在动作栏
/titleraw @a actionbar {"rawtext":[{"text":"♪ 一闪一闪"}]}
`

- 歌词来自 MIDI 的 lyrics 元事件（UTF-8），没有歌词时每 2 秒在动作栏显示「曲名 · 进度」
- 文本会自动转义（引号、反斜杠）并截断到 60 字符，保证 JSON 合法
- 可以单独关掉「歌词/曲名」而不影响音乐播放
- 命令在浏览器端调试：CQMusic.titleCommand("♪ 测试", "actionbar")

> 提示：	itleraw 需要目标玩家有权限（@a 全员，命令由连接的游戏客户端执行）。


## 界面（v2，像结构导入那样）

- **导入音乐**：文件框 + 上传并解析 / 移除
- **统计卡**（有颜色）：音符数（蓝）、总时长（绿）、歌词行数（黄）、已发送（紫）
- **彩色音轨时间轴**：按音色上色（钢琴蓝 / 贝斯青 / 合成主音浅蓝 / 鼓绿），
  底部有秒数刻度，播放时有黄色播放头实时移动
- **进度条**：渐变蓝→青→绿，下面显示「已播放 / 总时长（百分比）」和已发送命令数
- **MP3 转 MIDI（内置）**：上传 MP3 → 自动转成 MIDI → 自动载入音乐盒，可下载 .mid
  进度条为黄→橙→红渐变，统计卡显示 识别音符 / 估算 BPM / 音频时长

## 内置 MP3 → MIDI（纯前端实现）

流程：

```
MP3 → WebAudio decodeAudioData（解码）
    → 降采样到 11025Hz 单声道
    → 逐帧(1024/256) 自相关音高检测（取首个强峰，避免八度错误）
    → 按音高连续段切成音符，过短片段合并
    → 由音符间隔估算 BPM（50~200 区间折叠）
    → 写出标准 MIDI（SMF format 0，钢琴音色）
```

特点：

- 不依赖任何外部库 / 服务，离线可用
- 单音旋律（哼唱、钢琴单手、游戏 8bit 音乐）效果最好
- 和弦、复杂混音会被简化成一条主旋律
- 转换后自动载入音乐盒，可直接试听 / 发到游戏 / 再转成 playsound

调试接口：

```js
CQ_MP3.convertBase64(b64, "test.mp3")
// -> { notes, bpm, duration, pitches:[...音符编号], debug:{...} }
CQ_MP3.state()
CQ_MP3.download()
```

实测（合成测试曲 C4-D4-E4-G4-E4-D4-C4，120BPM）：

```
识别结果：60, 62, 64, 67, 64, 62, 60   <- 完全正确
估算 BPM：123（原曲 120，误差 2.5%）
时长：3.5s（原曲 3.5s）
```
